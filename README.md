# kakeibo

家族で使うためのブラウザ家計簿アプリです。取引一覧、直接入力、月別ダッシュボード、CSV 取込、カテゴリマッピングを Web でまとめて扱います。

- 本番: https://kakeibo-mu-two.vercel.app
- モバイル版リポジトリ: https://github.com/hiyamuuugh/kakeibo-app

## セットアップ

```bash
npm install
copy .env.example .env
npm run db:seed
```

`.env` では少なくとも次を設定します。

- `DATABASE_URL`: Neon / PostgreSQL 接続先
- `APP_PASSWORD`: 家族共通のログインパスワード
- `APP_SESSION_SECRET`: セッション署名用の長いランダム文字列
- `GOOGLE_VISION_API_KEY`: レシート OCR を使う場合のみ

## デプロイ関連

`master` への反映で Vercel がデプロイされます。アプリはブラウザ利用前提で、iOS アプリ配布は行いません。

### 身内のみアクセス

認証はアプリ内ログイン画面で行います。未ログイン状態では画面と API の両方を `middleware` でブロックします。

本番で必要な環境変数:

- `APP_PASSWORD`
- `APP_SESSION_SECRET`
- `DATABASE_URL`
- `GOOGLE_VISION_API_KEY`（OCR を使う場合）

Vercel の Environment Variables に同じ値を設定してください。

### PWA

このアプリはブラウザ版をホーム画面追加しやすいようにしてあります。

- `manifest.webmanifest` を配信
- `appleWebApp` / `themeColor` を設定
- `ホーム画面に追加` ボタンを対応ブラウザで表示

オフライン対応までは入れていません。主目的はスマホからアプリっぽく開きやすくすることです。

### 底値帖と画面の配色

- PC のメニューバーとスマホの下部メニューの「入力」の右隣に「底値帖」を表示します。
- 「底値帖」はアプリ内の `/price-notes` を開きます。家計簿と同じログインで利用できます。
- 商品名・カテゴリ・単位で商品をまとめ、購入店、税込価格、送料、内容量、購入日を PostgreSQL に保存します。
- 内容量と送料は任意入力です。空欄の内容量は未入力として保存し、送料は0円として扱います。任意の入力欄には `(任意)` を表示します。
- 商品のすべての記録に内容量がある場合は、送料込みの単価で比較します。内容量未入力の記録を含む場合は、送料込みの価格で比較します。内容量が空欄のときは、内容量や単価の表示自体を省きます。kg／g、L／mlは自動換算します。異なる単位（個とgなど）は別商品として扱います。
- 検索、カテゴリ絞り込み、並べ替え、履歴の表示・追加・編集・削除に対応します。底値帖は10件ずつ表示し、検索・カテゴリ・並び順の変更時は先頭ページに戻ります。購入先の区分は入力・表示しません。食品・日用品タブでは各行のカテゴリ名を省きます。履歴の削除はゴミ箱アイコン、編集はその左の鉛筆アイコンから行います。商品名・カテゴリ・内容量・単位・お店・価格・送料・購入日を変更できます。実データは空から始まり、以前のデモサイトのブラウザ保存データは自動移行しません。
- スマホのメニュー文字は省略せず折り返して表示します。デスクトップメニューは横幅が十分な1,024px以上で表示します。

#### 底値帖のデータベース

`PriceProduct` と `PriceRecord` の2テーブルを追加します。既存の家計簿テーブル・レコードは変更しません。

```bash
npm run db:price-notes
```

このコマンドは新規テーブルとインデックスだけを作る再実行可能なSQLです。`DATABASE_URL` が必要です。Vercel本番ビルド（`VERCEL_ENV=production`）では同じSQLを自動実行し、失敗時はデプロイを停止します。ローカルやプレビュー用DBでは上記コマンドを先に実行してください。内容量をNULLで保存できるようにするマイグレーションも適用します。既存の内容量は保持します。通常のPrismaマイグレーション用にも同じSQLを `prisma/migrations/20261112000000_add_price_notes/` に含めています。
- 全画面の基本配色は深い青、青みのある明るい背景、白いカードです。カテゴリの選択肢や一覧・凡例には、緑・青・黄土・紫・赤茶などを区別できる落ち着いた色を使います。家族全員と自分のタブは同じ選択色です。彩度を一律に下げず、プラスの金額・収入・収支がプラスの棒グラフは落ち着いた緑系、支出は赤茶系で表示します。アカウントの保存済み色データは保持します。

### 取込・入力

- CSV 取込: PayPay、PayPayカード、楽天カード、三菱UFJ銀行、三井住友銀行
- 直接入力: 支出 / 収入の切替、レシートOCR、カテゴリ選択
- カテゴリマッピング: 店舗名ルールの追加、削除、既存取引への再適用

### キャッシュフロー

ダッシュボードの右隣の `/cash-flow` は、今後の見通しグラフとシミュレーション用ルールだけを表示します。基本設定・ルールは家族共有でDBに保存し、家計簿の取引自体は追加・変更しません。

- 開始年齢と開始年は生年月日・現在日から自動計算し、終了年齢と現在の現預金を設定します。基本設定で積立ルールごとの現在の投資残高と、その他の非現金資産を手入力でき、グラフは即座に再計算します。保存すると次回も残高を復元します。積立ルールの残高は同じ値を編集し二重計上しません。その他の非現金資産は利回りなし・残高一定とし、既存の保存JSONでは0円に補完します。基本収支は家族全員の過去実績の月平均、または手入力の月額を使います。実績なしの場合は0円と表示します。
- 給料・保険料・教育費・住宅購入・車購入・ローン返済・生活費・年金・積立NISA・旅行のテンプレートを用意しています。定期収支は月額または年額と年齢区分で設定します。月額は年12回として計算し、給料は手取り額で設定してください。住宅・車は支出のみを計算し、ローン利用時は頭金・諸費用と返済ルールを分けます。資産価値・借入残高は自動計算しません。基本収支に含まれる費用を追加する場合は重複を避けて調整します。
- 年齢別ルール: 教育費等を0〜5歳、6歳以降などの年額で設定します。本人の年齢だけでなく、子ども等の開始年齢をルールごとに指定できるので、複数人を別ルールで扱えます。同一ルールの年齢区分の重複は拒否します。
- 積立・NISA: 開始運用資産、月末の積立、積立年齢の範囲、想定年率を設定します。年率を月利に換算して複利計算し、積立終了後も運用を続けます。積立は現預金から運用資産への移動として扱い、二重に支出計上しません。税・手数料・制度上の上限はモデルに含めません。
- 単発の支出: 本人または指定対象が何歳の年に旅行等へいくら使うかを設定します。
- グラフは開始時と、開始年齢から終了年齢までの各年齢の1年間を反映した概算です。ルールの収入・支出は基本収支に加算します。資金不足は現預金がマイナスの点として表示し、自動売却や借入利息の計算は行いません。
- `CashFlowPlan` テーブルの家族共有JSONに保存します。本番ビルドと `npm run db:price-notes` は追加の冪等マイグレーションも適用します。家計簿データから算出した平均収支は再読込で更新します。

### OCR

`/api/ocr` は Google Cloud Vision を使います。`GOOGLE_VISION_API_KEY` 未設定時は `503` を返します。

- カメラ画像はブラウザで向き・サイズを読み込み、最大4メガピクセル・長辺2,800px・2MiB以下のJPEGに変換してから送信します。大きな写真をそのまま送ることによるホスティング側の容量エラーを避けます。
- 画像の変換に対応できない形式はJPEG/PNGでの再選択を案内します。通信失敗や読み取り失敗でもボタンと写真入力を戻し、同じ写真で再試行できます。
- APIはファイル、容量、形式を検証し、Google応答内のエラー、空の認識結果、利用上限、認証・利用設定、タイムアウトを区別します。Googleの詳細メッセージはそのままブラウザへ返しません。
- 実際の認識には、Google Cloud側でVision APIの有効化・APIキーの権限・割り当て設定が必要です。

キャッシュフローの基本設定は初期状態で閉じたトグルです。グラフの大きな金額は億・兆・万で表示します。設定・ルール・残高は家族共有の1件を保存し、競合時は最後のDB書き込みが優先されます（自動マージなし）。未保存の変更やルール編集中は上書きを避け、通常は15秒ごと・画面復帰時に他端末の保存内容を取得します。

設定の「CSV取込の除外ワード」で、PayPay / PayPayカード / 楽天カード / セゾンカード / 三菱UFJ銀行 / 三井住友銀行ごとにトグルを開いてワードを登録・削除できます。正規化した部分一致で今後のCSV取り込みのみをスキップします。同じワードを別の取り込み元にも登録でき、各一覧は10件ずつ表示します。既存の共通除外ワードはマイグレーションで6つの取り込み元へコピーし、これまでの除外動作を維持します。


キャッシュフローの「年毎」は全ての年齢を1年刻みで並べた横スクロール表示です。終了年齢の右端でスクロールが止まります。実績平均は家族全員の全履歴のうち、記録がある終了済みの月を対象に月平均収入−月平均支出で計算します（今月・未来・未記録月を除外）。画面の「計算の根拠」に対象期間・件数・総額・月平均・計算式を表示します。手入力の基本収支がある場合はその値を優先し、別途明示します。AIや外部サービスへの送信は行いません。

キャッシュフローでは全期間に加え、1年単位・5年単位・10年単位の横スクロール表示を選べます。表示の間隔を変えても、毎年の資産計算と途中のルールは維持します。

AI予測の線は、アプリ内の回帰学習モデルによる予測です（生成AI/API接続ではありません）。直近24記録月までの収入・支出を別々に、12か月半減期の重み・正則化12×重み合計のリッジ回帰で学習します。3か月未満や最新記録が3か月超前の場合は非表示にします。最初の12か月の予測額は0〜学習期間の最大額に制限して整数円へ丸め、その後は予測月平均収支を固定します。AI線では手入力基本収支の代わりに予測収支を用い、現残高・投資利回り・年齢別ルールは通常試算と共通です。学習式・係数・対象月・最初の12か月の予測を画面に表示します。家計簿を外部サービスへ送信しません。

計算の根拠は初期状態で閉じたトグルです。「AI予測への指示」では、過去3〜120か月の対象期間と収入/支出の補正（−90〜100%）、対応形式の短い指示文を設定し、共有プランのJSONへ保存します。過去月数は暦月の範囲で、欠損月を0扱いにしません。指示文は例「過去12か月を考慮して。支出を10%増やす。」を設定へ変換し、未対応の自由文や重複指示はエラーにします。通常試算には適用せず、予測線の回帰結果に補正を掛けます。生成AIや外部送信は使いません。

新規ルールの区分は1つから始まり、必要に応じて追加できます。テンプレートはネイティブ選択欄で一覧から選びます。収入/支出と金額単位は横並びです。年齢/西暦の基準を選択でき、西暦は基準年（基本設定のシミュレーション開始年）に対する実年で毎年の期間・単発支出・積立期間を判定します。既存の年齢指定データは従来通り計算します。

予測指示パネルは基本設定と同じ開閉ボタンで初期状態は閉じています。入力は指示文のみで、解釈した対象期間・収入/支出の調整を「指示のまとめ」に表示します。未適用の内容はプレビューと明記します。数値設定のみの旧データは指示文へ変換して復元し、空欄で適用すると過去24か月/補正なしへ戻します。まとめはアプリ内で解釈した設定から生成し、外部の生成AIは使用しません。計算の根拠パネルはルール一覧の後、画面の一番下に配置します。

設定のプロフィールで任意の生年月日を登録できます（Member.birthDate、DATE型）。キャッシュフローの基準プロフィールは共有プランのreferenceMemberIdで保存し、未指定時は生年月日のある最初のプロフィールを使います。端末のアカウント切替で基準人物は変わりません。開始年齢・開始年は日本時間の現在日と生年月日から毎回解決し、日付変更/画面復帰時にも更新します。未登録時は年齢を推測せずプロフィール設定へ案内します。翌年は当日の満年齢で開始し、入力残高はそのまま現在の起点として使い、過去の予測利益を自動加算しません。本人の絶対年齢/西暦ルールは維持し、別人の開始年齢は保存年からの経過年分を進めて二重加算を避けます。

1・5・10年表示は資産合計の変化を優先し、現預金/非現金資産の内訳はチェックで追加できます。資産額の2%を縦軸の最低幅にする処理を廃止し、大きな残高の狭い表示範囲では基準額を明記して差額目盛りを使います。ツールチップと実際の計算額は絶対額のままです。

「年別の資産比較」では、通常試算/回帰予測を切り替え、2つの西暦の年末残高を左右で比較できます。現預金・投資残高・その他資産・合計と、各積立ルールの残高/試算元本（開始残高＋開始後の積立）/試算開始後の累計運用損益を表示します。差額は右−左、増減率は差額÷左の残高で、比較元が0円以下の場合は率を表示しません。残高増減には追加積立を含み、運用利回りとは別です。比較できる年は現在から設定した終了年齢までです。表示操作では共有プランや取引を書き換えません。

CSV取り込み通知は、選択中のアカウントについて今月を除く過去6か月の未取り込み月を表示します。利用履歴のあるCSV取り込み先が対象で、初回は6取り込み先を表示します。既存のCSV明細日付と `CsvImportMonth` の履歴で判定し、今後の取り込みでは除外・重複明細の月も履歴に残します。明細がない月や部分的な取り込みの完全性は判定できません。「先月分のCSVを取り込んでください。」の右の「取込済」を押すと、選択中のアカウントと通知を表示した月を `CsvReminderAcknowledgement` に保存し、その月は別端末を含め非表示にします。翌月は新しい通知の対象になります。取込済の操作は通知の確認状態だけを記録し、CSV明細や月別の取り込み履歴は変更しません。

設定画面の「毎月の予算」で家族共通・アカウント別の全体額と支出カテゴリ別の予算を保存できます。予算の入力は万円単位（小数点以下4桁まで）で、保存・支出との比較は円の整数に換算します。空欄は未設定、0は支出を予定しない予算です。全体額が未設定ならカテゴリ予算の合計を全体の上限として使用します。ダッシュボードでは表示中の月と対象の記録済み支出を比較し、カテゴリ予算の未設定支出も全体に含めます。毎月の設定は過去の月にも適用され、従来の家族共通の月別カテゴリ予算がある場合はその月の設定を優先します。設定は `MonthlyBudgetPlan` に対象ごとに保存し、最後の保存が反映されます。

マンスリーレポートは選択月のカテゴリ別支出額・割合・前月比・直前3か月の平均と平均との差を表示します。支出記録のない月は平均から除き、記録済みの月に存在しないカテゴリは0円として扱います。前月の記録がない場合は古い月を前月として代用しません。比較対象の月と計算方法はパネル内で確認できます。

設定画面のアカウント・毎月の予算・プロフィール・カテゴリマッピング・CSV取込の除外ワード、および各パネル内の開閉一覧は共通の `SettingsPanel` を使います。見出し右側の下向き矢印、展開時の上向き矢印、見出し全体での開閉、初期状態の非表示を統一しています（予算への直接リンクは開いた状態）。

2026-11-18の依頼によるCSV除外ワード全削除は `20261118040000_clear_import_exclusions` で一度だけ実行します。`AppDataMigration` の記録と削除を同一トランザクションで行い、後から登録したワードを再デプロイ時に消しません。取引・カテゴリマッピング・CSV取り込み履歴は削除対象に含みません。
